# Requirements: «НОВОСТИ ПОТОКА» — секция новостей/событий

Дата: 2026-10-01 · Режим: CE Brainstorm (добавление фичи) · Статус: ожидает утверждения

## Problem

У сайта нет места, где ученики и сообщество видят актуальную информацию: выход новых этапов курса, ивенты/сессии, важные объявления. Сейчас об этом можно только «рассказать» — на сайте такого фида нет. Нужен отдельный топик «НОВОСТИ ПОТОКА»: актуальный feed + календарь будущих событий, где посты появляются сами по заранее заданным датам и которые владелец может пополнять без программирования.

## Goals

1. Новый пункт навигации верхнего уровня «НОВОСТИ ПОТОКА» (иконка Lucide, стиль как у остальных пунктов).
2. Фид из постов: каждый пост — дата, заголовок, тип (этап / ивент / инфо), обложка (опционально), тизер; полный текст раскрывается прямо в фиде («читать полностью ↓»), без отдельных страниц.
3. Два вида фида: таймлайн (как на референсе «НОВОСТИ СООБЩЕСТВА») и сетка карточек — переключатель, по умолчанию таймлайн.
4. Блок «Впереди» сверху фида: будущие события списком с датами, типом и обратным отсчётом (дней).
5. Scheduled publishing: пост с датой в будущем скрыт до наступления даты и появляется сам, без пересборки/коммита со стороны владельца.
6. Добавление поста = один .md-файл в `docs/news/posts/` с frontmatter + git commit (или голосовая просьба к ассистенту). Никакой админки/бэкенда.
7. Стартовый контент: пост «Добро пожаловать» (опубликован) + 2–3 демо-поста, включая один с будущей датой для демонстрации автопоявления. Владелец заменит их на реальные.

## Non-goals

- Не трогаем React-сайт pepel4two.ru (другой кодбейс; скриншоты — только визуальный референс).
- Нет бэкенда, форм, админки, авторизации, комментариев.
- Нет визуального календаря «сетка месяца» — только список «Впереди».
- Нет отдельных URL-страниц на каждый пост (всё раскрывается в фиде).
- Не меняем остальные секции сайта.

## Approach options

### A. Одна страница фида + маленький локальный плагин MkDocs (рекомендуется)

Плагин сканирует `docs/news/posts/*.md`, читает frontmatter и встраивает JSON всех постов (включая будущие) в страницу `news/index.md`. JS рендерит «Впереди» + таймлайн/карточки, скрывает будущие посты до их даты (клиентское раскрытие).

- Плюсы: 1 страница, ~150–250 строк кода, добавление поста = файл+коммит, автопоявление без пересборки, полный контроль над вёрсткой под палитру сайта.
- Минусы: контент будущих постов присутствует в HTML-источнике (для публичных новостей приемлемо); тело постов не индексируется поиском Material по умолчанию (можно добавить через `search` — опционально).

### B. Каждый пост = отдельная страница MkDocs + генерируемый индекс

Плагин генерирует index-страницу со списком, будущие посты отфильтровываются при сборке.

- Плюсы: у каждого поста свой URL (SEO/поиск), контент будущих постов не попадает в HTML индекса.
- Минусы: противоречит решению «всё раскрывается в фиде, без отдельных страниц»; автопоявление по дате потребует либо клиентского скрытия на индексе (тогда URL всё равно виден), либо cron-пересборки — лишняя сложность.

### C. Гибрид A+B: фид + отдельные страницы постов

Максимальная гибкость, но двойной объём работы и дублирование контента. На текущем масштабе (десятки постов в год) избыточно.

## Recommended direction

**Вариант A.** Он точно соответствует принятым решениям (раскрытие в фиде, автопоявление без участия владельца, минимум кода). Контент новостей публичный — присутствие будущих постов в HTML не является проблемой.

### Формат поста (контракт для владельца)

```markdown
---
title: "Название поста"
date: 2026-10-15          # дата публикации (пост появится в фиде в этот день, время — 00:00 МСК)
type: этап                # этап | ивент | инфо
image: assets/news/cover.png   # опционально; без картинки — заглушка в стиле сайта
teaser: "Короткое описание для фида (1-2 предложения)"
---

Полный текст поста... (markdown, ссылки, изображения)
```

### Поведение

- `date` > сегодня → пост только в блоке «Впереди» (дата, заголовок, тип, «N дн.»); в таймлайне/карточках не показывается.
- `date` <= сегодня → пост в фиде; сортировка по дате убыванию; нумерация 01, 02… как на референсе.
- Переключатель вида: Таймлайн / Карточки (состояние можно запомнить в localStorage).
- Фильтр по типу (этап/ивент/инфо) — чипы над фидом; «Все» по умолчанию.
- Пустое состояние: если постов нет — заглушка «Пока тихо...».
- Часовой пояс: дата без времени, граница суток — 00:00 МСК (UTC+3).

### Навигация и размещение

- Топ-уровень nav в `mkdocs.yml`: пункт «НОВОСТИ ПОТОКА» с Lucide-иконкой (`newspaper`), сразу после «Главная».
- Страница: `docs/news/index.md`; посты: `docs/news/posts/*.md`.
- Стили — в `extra.css` на существующих design tokens (`--accent-orange`, `--bg-card`, `--text-main`), дублирование для светлой/тёмной темы как принято в проекте. Иконки только Lucide, цвет иконок `--accent-orange`.

### Стартовый контент (демо)

1. «Добро пожаловать в Новости Потока» — date = день запуска, type: инфо.
2. Демо-пост «Вышел новый этап курса» — прошедшая дата, type: этап.
3. Демо-пост «Ивент: сессия на Discord» — будущая дата (+7 дней), type: ивент (демонстрирует блок «Впереди» и автопоявление).

## Success criteria

1. `mkdocs build` проходит; пункт «НОВОСТИ ПОТОКА» в навигации ведёт на фид.
2. Демо-пост с прошедшей датой виден в таймлайне и в карточках, текст раскрывается вниз.
3. Демо-пост с будущей датой виден только в «Впереди»; после наступления даты (проверка: подмена даты/JS) появляется в фиде без пересборки.
4. Новый .md-файл в `docs/news/posts/` + rebuild → пост появляется в фиде; без frontmatter-ошибок сборка не падает (валидация с понятным сообщением).
5. Вёрстка соответствует палитре сайта в тёмной и светлой теме, на мобильном — одна колонка, таймлайн/карточки читаемы.

## Domain vocabulary

| Термин | Значение |
|---|---|
| Пост | Единица контента фида: .md-файл с frontmatter (title/date/type/image/teaser) + тело |
| Тип поста | `этап` (выход этапа курса), `ивент` (сессия/батл/стрим), `инфо` (важное объявление) |
| «Впереди» | Блок будущих событий: посты с date в будущем, список с обратным отсчётом |
| Scheduled publishing | Автопоявление поста в фиде по дате из frontmatter без пересборки сайта |
