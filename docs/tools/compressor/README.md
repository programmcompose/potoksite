# Инструмент «Компрессор» — справка для агентов

> Этот файл — документация для AI-агентов (и людей), работающих с инструментом.
> Он **не публикуется** на сайт: исключён из сборки через `exclude_docs` в `mkdocs.yml`.
> Не добавляй сюда контент, который должен попасть на публичный сайт — для этого есть `index.html`.

## Что это

Страница интерактивного инструмента по уроку Compression (этап 2). Один URL, два режима во вкладках:

1. **Компрессор** (`data-pcp-tab="compressor"`) — виджет с параметрами: крутишь Threshold/Ratio/Knee/Attack/Release/Makeup/Dry-Wet на синтезированном бите или своём треке; видишь волну (dry+wet), GR-метр с peak-hold и кривую передачи с живой точкой. A/B bypass по кнопке или клавише **B**.
2. **Слепой тест A/B** (`data-pcp-tab="blind"`) — тренировка слуха: два звука, один сухой, второй сжат; угадай, какой без компрессии. Никаких визуальных подсказок (ни волны, ни метра).

## Файлы

| Файл | Роль |
|---|---|
| `docs/tools/compressor/index.html` | Страница инструмента: шапка, вкладки `.pcp-tabs`, два `<section data-pcp-panel>`, подсказки. Подключает оба JS явно (см. ниже про двойную загрузку). |
| `docs/assets/javascripts/compressor-widget.js` | Виджет «Компрессор» + **публичный API** `window.PotokCompressor`. Загружается глобально через `extra_javascript` в `mkdocs.yml` (виджет встроен в урок `etap2/compression-kompressiya.md` тегом `<div class="potok-compressor"></div>`). |
| `docs/assets/javascripts/compressor-blind.js` | Слепой тест. Живёт только на странице инструмента, использует API из widget-файла (поэтому в `index.html` подключается ПОСЛЕ него). |
| `docs/assets/stylesheets/compressor.css` | Стили обоих режимов: классы `.pcp*` (виджет) и `.cbt*` (слепой тест), плюс общие `.pcp-tabs`. Подключён глобально через `extra_css`. |

**Двойная загрузка:** на странице инструмента `compressor-widget.js` подтягивается дважды (глобально из mkdocs.yml + явно в index.html). Это безопасно: boot() защищён флагом `root.__pcpInited`. Не «чинить».

## Архитектура compressor-widget.js

Всё в одном IIFE, ES5-стиль (`var`, prototype, без классов и стрелок) — держать этот стиль при правках.

### Синтез сигнала
- `synthLoop(ctx, mode)` — синтезирует луп: **90 BPM, 2 такта × 16 шагов** (`LOOP_SEC` ≈ 5.33 с), моно. Режимы: `'beat'` (kick+snare+hats), `'kick'`, `'snare'`. Kick — синус со свипом 150→50 Гц + шумовой клик; snare — треугольник 195 Гц + bandpass-шум 1.8 кГц; hats — highpass-шум 7.5 кГц. Пик нормализуется до **−6 dBFS** (`DRY_PEAK_DBFS`).

### Движок компрессии
- `processLoop(ctx, dryBuf, p)` — оффлайн-обработка всего буфера:
  - огибающая — однополюсный follower: attack/release как постоянные времени (мс);
  - кривая передачи — **soft knee** (`softKneeOut(db, thresh, ratio, kneeDb)`), knee в дБ;
  - makeup gain + мягкий лимитер `tanh` на ±0.98;
  - возвращает `{ buffer, gr[] (GR по сэмплам, дБ), envDb[] (входной уровень огибающей), avgGr }`.
- Параметры `p`: `threshold` (дБ), `ratio`, `knee` (дБ), `attack`/`release` (мс), `makeup` (дБ), `mix` (%).

### Загрузка своего трека
- `prepareTrack(ctx, file, maxSec=120)` — FileReader → `decodeAudioData` → миксдаун в моно → обрезка до 2 минут → пиковая нормализация до −6 dBFS. Лимиты: **30 МБ** (`MAX_FILE_BYTES`), форматы — что декодирует браузер (WAV/MP3/OGG/FLAC/M4A).

### UI виджета
- Параметры — **крутилки (knobs)** `.pcp-knob`: canvas-рендер (тики по окружности, дуга значения, указатель; ход 270°). Управление: вертикальный drag (Shift — точный), колесо мыши, стрелки/PageUp/Home/End при фокусе (`role="slider"`, aria-*), **dblclick — сброс к дефолту**. Класс `Knob` в widget-файле; ratio/attack/release — логарифмическая шкала (`tOf`/`valueOfT`), остальные линейные.
- Пресеты `PRESETS`: «Мелодия 2:1 slow», «Snare punch fast», «Bus 1.5:1» (значения из таблицы «Применение» урока).
- Источники: Бит / Kick / Snare / Свой трек; тумблер **Auto makeup** — подставляет `makeup = avgGr` (с клампом ±12 дБ).
- Ререндер wet при смене параметров — debounce 150 мс (`scheduleRerender`); при воспроизведении новый wet-буфер кроссфейдится на лету без остановки.
- GR-метр: текущий GR в окне ±3 мс вокруг позиции + peak-hold 900 мс; цвет зелёный/жёлтый/красный (<3/<8/≥8 дБ).

### Публичный API (`window.PotokCompressor`)
```js
synthLoop(ctx, mode)      // AudioBuffer лупа
processLoop(ctx, buf, p)  // { buffer, gr, envDb, avgGr }
prepareTrack(ctx, file)   // Promise<AudioBuffer> (моно, ≤2 мин, пик −6 dBFS)
fmtDur(sec)               // "1:05"
MAX_TRACK_SEC             // 120
LOOP_SEC                  // длительность синтезированного лупа
dbToLin(db)
stopAll()                 // остановить все живые виджеты (используется при переключении вкладок)
```

## Архитектура compressor-blind.js

IIFE, ES5. Класс `BlindTest` на корень `.potok-compressor-blind`.

### Механика раунда
- Два пада «Звук 1/2»: один играет `dryBuf`, другой `wetBuf`. Слот сухого (`drySlot`) рандомится каждый раунд.
- Общая случайная точка входа в луп для обоих звуков, квантованная по 32 шагам — чтобы не было позиционной подсказки («в начале тише»).
- Ответ: кнопки «Звук N — без компрессии». После ответа пады блокируются, показывается вердикт.

### Настройки меняются каждый раунд (ключевая фича)
- `PROFILES` — 4 «характера» сжатия с диапазонами параметров:
  1. плотное сжатие (низкий порог, ratio 6–12, быстрый attack);
  2. punch (медленный attack 30–90 мс — транзиенты проходят);
  3. «дыхание» (длинный release 400–700 мс);
  4. лёгкий glue (ratio 2–3.5, высокий порог).
- `randomParams()` берёт случайный профиль и дёргает значения внутри диапазонов → раунды не повторяются.
- `makeWet(dryBuf)` перекатывает настройки до `MAX_ROLLS=10`, пока `avgGr ≥ MIN_AVG_GR` (2 дБ) — иначе сжатие может быть незаметным; при неудаче — `FALLBACK` (−20 дБ / 8:1 / 5 мс / 120 мс).
- **Auto makeup**: RMS wet подгоняется под RMS dry (`matchRmsMakeup`, кламп ±12 дБ) — разница между звуками только в характере, не в громкости.

### Разбор после ответа
После выбора (верного или неверного) показываются:
- чип `.cbt-result-params` с применёнными `Threshold · Ratio · Attack · Release`;
- строка `.cbt-result-desc` от `describeParams(p)` — что этот набор делает со звуком (быстрый attack срезает атаку, длинный release даёт «дыхание» и т.д.).

Во время раунда настройки **не показываются** — это часть слепоты теста.

### Прочее
- Счёт `correct / total` в шапке; кнопка «Следующий раунд →».
- Источник: синтезированный бит или свой трек (`prepareTrack`) — при смене источника раунд перезапускается.
- Переключение вкладок глушит аудио другого режима (в blind.js — `initTabs`, в widget — `stopAll`).

## Конвенции проекта (обязательно)

- **Иконки**: только Lucide (`<i data-lucide="...">`), цвет иконок — `--accent-orange`. Никаких эмодзи/FontAwesome.
- **CSS-токены**: в `compressor.css` у `.pcp, .cbt` локальные переменные `--pcp-*` с фолбэками на токены сайта (`--bg-card`, `--border-default`, `--text-main`, `--accent-orange`). Новые цвета — только через токены; тёмная/светлая темы дублируются в `extra.css`.
- **JS**: ES5, IIFE + `'use strict'`, prototype-методы. Без внешних зависимостей (кроме lucide).
- Изменения в `docs/assets/*` влияют на ВСЕ страницы (глобальные extra_css/js) — проверяй, что не сломал виджет в уроке compression.

## Как проверять изменения

1. `node --check docs/assets/javascripts/compressor-blind.js` (и widget) — синтаксис.
2. Headless-симуляция: оба файла eval'ятся в Node со стабами `document`/`AudioContext` (FakeBuffer с реальными сэмплами из `synthLoop`) — можно прогнать раунды и проверить вывод после ответа. Реальный Chrome через Playwright в этой среде может не запускаться (`spawn UNKNOWN`).
3. `mkdocs build` — сборка сайта (site/ в gitignore, коммитится только docs/).
4. Git: по завершении изменения — сразу `git add . && git commit "x: ..." && git push` (правило из AGENTS.md).
