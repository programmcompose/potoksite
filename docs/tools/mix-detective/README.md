# Mix Detective — тренажёр инженерного мышления в сведении

Одностраничный инструмент (self-contained HTML, без внешних аудиофайлов). Ученик слушает проблемный микс, определяет главную проблему, выбирает первый инструмент и объясняет решение. После проверки — вердикт по каждому пункту, пошаговый «инженерский разбор» и A/B Bad/Fixed. Второй режим — мини-DAW «Почини сам».

Файл: `docs/tools/mix-detective/index.html` (копируется в `site/` статически).

## Режимы

### 1. Кейсы (Detective)
5 кейсов с уровнями сложности:

| id | уровень | проблема | лучший первый шаг |
|---|---|---|---|
| vocal-too-low | beginner | вокал тонет | Volume / automation |
| muddy-mix | beginner | грязь 200–500 Гц | EQ (HPF/срез) |
| weak-kick | intermediate | бас маскирует кик 60–100 Гц | EQ (carve) |
| harsh-vocal | intermediate | резкость 2–4 кГц + свист | EQ (срез/de-ess) |
| overcompressed | advanced | переконтроль динамики | Compressor (GR/attack) |

Проверка ответа: проблема (правильная/нет), инструмент (best / acceptable с пояснением / мимо), текст объяснения (мягкий анализ по ключевым словам + объём). Разбор инженера показывается всегда — в сведении нет единственного правильного ответа, учим последовательность рассуждений.

### 2. Почини сам (Fix-it mini-DAW)
4 трека (VOCAL / BASS / DRUMS / SYNTH), на каждом: Volume, HPF, Peak EQ (фиксированная частота), Compressor, Reverb send. Старт — «несведённый» микс (`FIX_START`): тихий размытый вокал, громкий грязный синтез. Метрики пересчитываются на лету после каждого изменения (debounce 180 мс + очередь рендеров). Кнопка «Эталон A/B» играет `BASE_MIX`.

Метрики (шкала-инвариантные отношения, не абсолютные уровни):
- **Vocal presence** — доля энергии вокала в полосе 2–8 кГц от всей энергии микса в этой полосе.
- **Low balance** — «грязь» инструментала: E(150–800 Гц)/E(total) на сигнале (микс − вокал). Форманты вокала не считаются грязью.
- **Clarity** — доля полосы 3–8 кГц в общей энергии микса.

## Архитектура

Весь код в одном `<script>` (IIFE, `'use strict'`), разделён на части:

1. **Конфигурация и данные**: `SR=44100`, луп 32 шага @84 BPM (~6.6 с) + хвост 0.9 с; `CAL` — константы калибровки метрик; `BASE_MIX` (эталон), `FIX_START`; массив `CASES`.
2. **Синтез источников** (`synthDrums/Bass/Pad/Vocal`) — чистый JS в `Float32Array`, один раз при загрузке: кик со свипом 48→150 Гц + клик, снейр (triangle 196 Гц + BP-шум), хэты (HPF 7.5 кГц, открытые на off-beat); бас A1/F1 с гармониками; pad — аккорды saw через LPF 2.8 кГц; вокал — saw-мелодия через формантные bandpass (700/1600/2800 Гц) + вибрато. Нормализация пиков: инструменты −12 дБ, вокал −9 дБ.
3. **Рендер** (`renderMix(params, onlyTrack)`) — `OfflineAudioContext` (2 ch): на трек HPF → peaking EQ (частота `PEAK_FREQ`: vocal 3.2 кГц, bass 80 Гц, drums 6 кГц, synth 400 Гц) → DynamicsCompressor (если включён) → gain; reverb send в общий Convolver (генерируемый импульс ~0.7 с); master gain + soft-clip WaveShaper. `onlyTrack='vocal'` глушит остальные треки (включая их sends — они идут после vol).
4. **Анализ** (`analyzeBuffer`) — собственный FFT 4096 (Hann, hop N/2) по окну 1.2–4.8 с; полосовые энергии: sub 30–90, lowmid 150–400, mud 150–800, pres 2–8 кГц, high 3–8 кГц, total.
5. **Метрики** (`computeMetrics(mixBuf, vocalBuf)`) — см. выше; инструментал = поэлементная разность двух рендеров (линейно: sends идут после vol).
6. **Воспроизведение** — один `AudioContext`, loop-источник с кроссфейдом dip через общий gain-узел, offset сохраняется при смене буфера.
7. **UI** — вкладки, кейсы, проверки, strips (генерируются из `FIX_CONTROLS`), прогресс в localStorage (`mix-detective-v1`: solved/attempts/fixitBest), тема (`tools-theme`, общая со всеми инструментами), клавиатура: Space — play/stop, Enter — проверить.

## Калибровка метрик

Константы `CAL` подогнаны под синтезированные источники симуляцией в Node (те же RBJ-формулы biquad, что и Web Audio BiquadFilter; comp/reverb/shaper не моделируются):

```
node tests/mix-detective-calib.js
```

Скрипт извлекает основной `<script>` из `index.html`, пересобирает источники и проверяет:
- точность FFT (синус 100 Гц → правильный bin);
- старт fix-it (`FIX_START`) даёт низкий итог (<40%), эталон (`BASE_MIX`) — высокий (>80%);
- направление метрик на кейсах (vocal-too-low: VP падает; muddy-mix: LB/CL падают; weak-kick: CL падает).

**Правило:** при изменении источников (`synth*`), `PEAK_FREQ`, полос в `analyzeBuffer` или `BASE_MIX/FIX_START` — прогнать калибровку и при необходимости поправить `CAL`. Ориентиры: старт fix-it ≈ 5–20% по каждой метрике, эталон ≈ 85–100%.

## Как добавить кейс

Добавить объект в `CASES` (см. существующие):
- `id`, `level` (`beginner|intermediate|advanced`), `title`, `tags[]`, `brief`;
- `problemOptions[4]` + `correctProblem` — дистракторы должны быть правдоподобными;
- `toolOptions[4]` + `bestTool` + `acceptableTools{}` (пояснение для «работает, но не первым шагом»);
- `keywords[]` — подстроки (lowercase) для мягкого анализа текста ответа; 2+ попаданий = сильное объяснение;
- `breakdown[4]` — последовательность шагов инженера;
- `mixBad` / `mixFixed` — спецификации рендера через `cloneMix(BASE_MIX)` + правки.

Проверка A/B: `node tests/mix-detective-calib.js` печатает метрики bad/fixed каждого кейса — «плохой» микс должен отличаться по метрике, соответствующей его проблеме (для harsh-vocal/overcompressed отличие в динамике/резкости слышно на слух, метрики это не покрывают).

## Хук для реальных записей (v2)

Если у кейса есть поле `audio: { bad: 'cases/<id>/bad.wav', fixed: 'cases/<id>/fixed.wav' }` — вместо синтеза используется `fetch + decodeAudioData`. Структура папок под будущие записи:

```
docs/tools/mix-detective/cases/
├── vocal-too-low/{bad,fixed}.wav
└── ...
```
