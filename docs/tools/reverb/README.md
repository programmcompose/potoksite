# Инструмент «Reverb / Реверберация» — справка для агентов

> Этот файл — документация для AI-агентов (и людей), работающих с инструментом.
> Он **не публикуется** на сайт: исключён из сборки через `exclude_docs` в `mkdocs.yml`.
> Не добавляй сюда контент, который должен попасть на публичный сайт — для этого есть `index.html`.

## Что это

Страница интерактивного инструмента по уроку Reverb (этап 2). Один URL, два режима во вкладках:

1. **Реверб** (`data-prv-tab="reverb"`) — виджет с параметрами: крутишь Decay/Pre-Delay/Mix/Dry/HPF/LPF на синтезированном бите или pluck-тоне; в standalone-режиме (страница инструмента) — загрузка своего аудиофайла и микрофон. A/B bypass по кнопке или клавише **B**.
2. **Слепой тест A/B** (`data-prv-tab="blind"`) — тренировка слуха: два звука, один сухой, второй с реверберацией (небольшое примешивание wet); угадай, какой без эффекта. Никаких визуальных подсказок (ни волны, ни метра).

## Архитектура reverb-widget.js

Всё в одном IIFE, ES5-стиль (`var`, prototype, без классов и стрелок) — держать этот стиль при правках.

### Синтез сигнала
- `synthBeat(ctx)` / `synthTone(ctx)` — луп **80 BPM, 2 такта × 16 шагов** (`LOOP_SEC` = 6 с), стерео (моно-сигнал продублирован на оба канала). Beat: kick + snare + hats; tone: pluck-арпеджио A минор (треугольник с экспоненциальным затуханием) — чёткая атака, pre-delay и хвост слышны отчётливо. Пик нормализуется до 0.8 (`normalizePeak`).

### Движок реверба
- Живой виджет: `ConvolverNode` + сгенерированный импульс `makeImpulse(ctx, decay)` (стерео-шум с экспоненциальным огибающим `exp(-t·6/decay)`, усиленные ранние отражения первые 80 мс). Цепочка wet: `Source → PreDelay → HPF → LPF → Convolver → WetGain`; параллельно `Source → DryGain`. Пересборка импульса — debounce 120 мс.
- Оффлайн (для слепого теста): `processLoop(ctx, dryBuf, p)` — **асинхронный** (`Promise<{ buffer }>`), рендер через `OfflineAudioContext`:
  - вход = луп, повторённый `copies` раз; `copies = max(2, ceil(irLen/L) + 1)` — чтобы хвост из предыдущей итерации целиком уместился до начала окна вывода (wrap-хвост на границе лупа, как у реального реверба на лупящемся треке);
  - окно вывода `[ (copies−1)·L, copies·L )` → буфер длиной ровно `dryBuf.length`, можно играть с `loop=true`;
  - mono-импульс `makeImpulseMono` (та же форма, что у стерео), цепочка wet та же, что в живом виджете;
  - мягкий лимитер `tanh` на ±0.98 (сумма dry+wet может выбить пик).

### Загрузка своего трека
- `prepareTrack(ctx, file, maxSec=120)` — FileReader → `decodeAudioData` → миксдаун в моно → обрезка → пиковая нормализация до −6 dBFS. Лимиты: **30 МБ** (`MAX_FILE_BYTES`). Слепой тест вызывает с `maxSec = 60` (стоимость оффлайн-рендера).

### Публичный API (`window.PotokReverb`)
```js
synthLoop(ctx, mode)      // AudioBuffer лупа: 'beat' | 'tone'
processLoop(ctx, buf, p)  // Promise<{ buffer }> — dry + reverb, wrap-хвост, длина = buf.length
prepareTrack(ctx, file)   // Promise<AudioBuffer> (моно, ≤ maxSec, пик −6 dBFS)
fmtDur(sec)               // "1:05"
MAX_TRACK_SEC             // 120
LOOP_SEC                  // длительность синтезированного лупа (6 с)
dbToLin(db)
stopAll()                 // остановить все живые виджеты (используется при переключении вкладок)
```

## Архитектура reverb-blind.js

IIFE, ES5. Класс `BlindTest` на корень `.potok-reverb-blind`.

### Механика раунда
- Два пада «Звук 1/2»: один играет `dryBuf`, другой `wetBuf`. Слот сухого (`drySlot`) рандомится каждый раунд.
- Общая случайная точка входа в луп для обоих звуков, квантованная долями (32) — чтобы не было позиционной подсказки («в начале тише»).
- Ответ: кнопки «Звук N — без реверба». После ответа пады блокируются, показывается вердикт.

### Настройки меняются каждый раунд (ключевая фича)
- `PROFILES` — 4 «характера» пространства с диапазонами параметров: комната (decay 0.6–1.3), плита (1.2–2.2, яркий LPF/HPF), зал (1.8–3.5), собор (3.5–6.0, длинный pre-delay).
- `randomParams()` берёт случайный профиль и дёргает значения внутри диапазонов → раунды не повторяются. Wet-mix всегда «небольшое»: 15–45%.
- **Auto makeup**: после оффлайн-рендера RMS wet масштабируется под RMS dry (`matchRmsInPlace`, кламп ±12 дБ) — разница между звуками только в характере пространства, не в громкости.

### Асинхронность (отличие от компрессора)
- `processLoop` рендерит через OfflineAudioContext → wet-буфер появляется с задержкой (для бита <0.5 с, для длинного своего трека до пары секунд).
- Состояния: `wetReady`, `rendering`, `wantPlay`. Пока рендер идёт — статус «Готовим раунд…» (`.rbt-status`); нажатый пад запоминается в `wantPlay` и запускается после готовности.
- При смене источника/раунда: `wetReady=false, wetBuf=null`, новый `roundParams`; если ctx уже есть — рендер стартует сразу.

### Разбор после ответа
После выбора (верного или неверного) показываются:
- чип `.rbt-result-params` с применёнными `Decay · Pre-Delay · HPF/LPF · Wet`;
- строка `.rbt-result-desc` от `describeParams(p)` — что этот набор делает со звуком (длина хвоста = размер пространства, pre-delay сохраняет чёткость атаки, фильтры окрашивают хвост и т.д.).

Во время раунда настройки **не показываются** — это часть слепоты теста.

### Прочее
- Счёт `correct / total` в шапке; кнопка «Следующий раунд →».
- Источники: Бит / Тон / Свой трек (`prepareTrack`, ≤60 с) — при смене источника раунд перезапускается.
- Переключение вкладок глушит аудио другого режима (в blind.js — `initTabs` по `[data-prv-tab]`, в widget — `stopAll`).

## Конвенции проекта (обязательно)

- **Иконки**: только Lucide (`<i data-lucide="...">`), цвет иконок — `--accent-orange`. Никаких эмодзи/FontAwesome.
- **CSS-токены**: в `reverb-widget.css` у `.prv, .rbt` локальные переменные `--prv-*` с фолбэками на токены сайта (`--bg-card`, `--border-default`, `--text-main`, `--accent-orange`). Новые цвета — только через токены; тёмная/светлая темы дублируются в `extra.css`.
- **JS**: ES5, IIFE + `'use strict'`, prototype-методы. Без внешних зависимостей (кроме lucide).
- Изменения в `docs/assets/*` влияют на ВСЕ страницы (глобальные extra_css/js) — проверяй, что не сломал виджет в уроке reverb (`etap2/reverb-reverberatsiya.md`).

## Как проверять изменения

1. `node --check docs/assets/javascripts/reverb-blind.js` (и widget) — синтаксис.
2. `node Scripts/test_reverb_dsp.js` — headless-проверка DSP: стаб `OfflineAudioContext` с наивной конволюцией/биквадами; click-тест сверяет выход `processLoop` с точным эталоном круговой свёртки (steady-state реверб на лупе) → проверяется wrap-хвост, длина буфера, лимитер, идентичность при mix=0, `prepareTrack`, `synthLoop`.
3. Headless-симуляция blind.js: файл eval'ится в Node со стабами `document`/`AudioContext` — можно прогнать раунды и проверить вывод после ответа. Реальный Chrome через Playwright в этой среде может не запускаться (`spawn UNKNOWN`).
4. `mkdocs build` — сборка сайта (site/ в gitignore, коммитится только docs/).
5. Git: по завершении изменения — сразу `git add . && git commit "x: ..." && git push` (правило из AGENTS.md).
